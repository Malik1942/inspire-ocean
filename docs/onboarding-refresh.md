# Onboarding refresh (2026-07)

## Brief

- **Problem**: onboarding is six screens of abstract orientation that now duplicates what the seeded Introduction current teaches concretely in the Ocean; the two surfaces never reference each other, and pages 3 to 5 overlap in message (drift, resurface, ask are all "the Ocean gives back").
- **Who**: a brand-new user on first launch; also a user replaying it from Fast Capture settings.
- **Success**: fewer screens before the product; the user lands on the Ocean knowing the Introduction orb is there for them; Fast Capture still gets set up; nothing claims features the newest version does not have.
- **Constraints**: bilingual value-as-key catalog, no em/en dashes in copy, replayable from settings, keep the Fast Capture setup page (it binds real App Group prefs), keep the Canvas visual language.
- **Non-goals**: no coach-mark tutorial, no motion redesign, no re-seeding changes beyond copy alignment.

## Directions

- **A. Setup-only onboarding** (kill all concept pages): fastest entry, but loses the identity moment ("not another notes app") that the in-product introduction cannot deliver before the field renders, and replay-from-settings becomes a bare settings screen. Killed.
- **B. 3 concept pages + setup, explicit handoff** to the Introduction current on the setup page. Keeps the identity, capture, and gives-back arc; cuts the overlap. **Chosen.**
- **C. 1 combined identity+capture page + setup**: shortest, but cuts the resurface/ask priming, which is the least self-discoverable differentiator. Killed.

## Decision

Pages go 5 → 3: keep pages 1 and 2 verbatim (blessed zh), merge drift + resurface + ask into one "The Ocean gives back." page on the resurface visual. The setup page gains a closing handoff line pointing at the Introduction current. The Introduction node's body gains the Ask tab vs branch distinction and a Library mention so it covers all four tabs.
